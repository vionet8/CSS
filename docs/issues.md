### セールス・マーケ第一戦略のギャップ（2026-07-07 対応）

**戦略**: CSSは「これまで・これからのプロダクトのセールス/マーケを簡単にするツール」。
その観点で監査した結果、以下のギャップを特定し実装した。

| # | ギャップ | 対応 |
|---|----------|------|
| M1 | 構造分析が汎用フレーム（現状/問題/原因…）のみで、販促文脈の型がない | セールスフレームワーク分析を追加: **PASONA / AIDMA / FAB**（`POST /projects/{id}/marketing/analyze`）。結果はロジック構造タブにフレームワークバッジ付きで表示 |
| M2 | プロダクト名・ターゲット顧客・訴求ゴール・トーンを保持する場所がない | **プロダクトプロファイル**を追加（`PUT /projects/{id}/marketing/profile`、`assets.marketing_profile` に保存）。分析・スライド生成・素材生成すべてに自動反映 |
| M3 | アウトプットがスライドのみ。「相互変換」理念に反して販促チャネル向け素材に変換できない | **販促素材生成**を追加: X投稿×3案 / LPコピー一式 / セールスメール×2案 / プレスリリース / 広告コピー×5案（`POST /projects/{id}/marketing/assets`、`assets.marketing_assets` に永続化、UIにコピー・再生成・削除） |
| M4 | スライド生成がセールスピッチを意識しない（CTAで締まらない） | プロファイル設定時は生成プロンプトにセールス文脈を注入し、最終スライドをCTAで締めるよう指示 |
| M5 | 未使用だった `assets` JSONカラム | マーケデータの保存先として活用（スキーマ変更・マイグレーション不要） |

テスト13件を追加（`tests/test_marketing.py`）: フレームワーク/素材タイプ検証、プロファイル永続化、素材の追加が既存素材を壊さない回帰、構造→素材テキスト変換、スライド生成へのプロファイル伝播。

### LP第一ワークフローの強化（2026-07-07 追加）

「LPを最初に作る」進め方に合わせて、以下を追加実装した。

| # | ギャップ | 対応 |
|---|----------|------|
| M6 | LPや素材にターゲット設計が既に書かれている場合、それを手で転記して評価する必要があった | **プロファイル審査**を追加（`POST /projects/{id}/marketing/profile/audit`）。素材からプロダクト名・ターゲット・ゴール・トーンを自動抽出し、項目ごとに OK/曖昧/欠落 で審査。読み取れた値はワンクリックでフォームに反映（保存はユーザー確認後） |
| M7 | ターゲット設計が素材から読み取れない場合に、何を決めるべきかの導きがなかった | 審査結果に**確認質問**を含める（例:「読者に最終的に取ってほしい行動は？」）。欠落項目は黄色の確認ボックスで表示 |
| M8 | ChatGPT等の外部AIで作った素材を活かす経路がなく、貼り付けても丸ごと1テキスト扱いだった | **外部素材の取り込み・分解**を追加（`POST /projects/{id}/marketing/materials`）。素材を断片（主張/ベネフィット/根拠・実績/事例/キャッチコピー/CTA）に分解して蓄積し、以降の構造分析・素材生成プロンプトに自動で散りばめる。断片は個別削除可、保存上限200件・プロンプト注入上限40件 |

テスト8件を追加（`tests/test_marketing_materials.py`）。合計50件。

| # | ギャップ | 対応 |
|---|----------|------|
| M9 | キャッチコピーだけを大量に出して比較・選定する使い方ができなかった | 素材タイプ「**キャッチコピー**」を追加。**切り口の異なる10案**（ベネフィット直球/数字・実績/問いかけ/損失回避/ターゲット呼びかけ/意外性・逆説/比喩/社会的証明/緊急性・限定/情緒・共感）を各テーマ名付きで生成。素材に実績数値がない場合は捏造せず別表現に置き換えるガード付き |
| M10 | LPコピー（文章）までしか作れず、公開できるLP本体は手作業だった | **LP HTML書き出し**を追加（`GET /projects/{id}/marketing/lp.html`）。生成済みLPコピーから、ヒーロー→ベネフィット→CTAの一枚もの・レスポンシブ・OGP付きのセルフコンテインドHTMLをテンプレートで決定的に生成。CTAリンクとアクセント色を指定でき、UIからプレビュー・ダウンロード可能。コピーはHTMLエスケープ、CTA URLは http(s)/相対のみ許可（javascript:等を拒否）、アクセントは#RRGGBB検証 |

## 運用ルール（課題管理の仕組み）

1. **課題を見つけたら**: この台帳の「未解決」に1行追加する（GitHub Issue を立てた場合はリンクを貼る）
2. **着手するとき**: ブランチを切り、対応するテストを先に書く
3. **解決したら**: CI が緑であることを確認し、「解決済み」セクションへ移動
4. **リリース前チェック**: `backend: python -m pytest` / `frontend: npm run build` が両方通ること（CIが自動で検証）
